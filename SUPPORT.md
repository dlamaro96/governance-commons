# Community support

Use the repository's [issues](https://github.com/dlamaro96/governance-commons/issues)
for reproducible bugs, feature proposals and connector requests. Security details
belong in the private route described in SECURITY.md. The project is maintained
on a best-effort basis; no response SLA, paid service or production certification
is implied.

Include the exact commit/version, operating profile, architecture, sanitized
`./dev doctor` output, command and exit code, reproduction using synthetic data,
expected/actual behavior and relevant correlation IDs. For a source integration,
include its product/API version, adapter and capability, fixture/local/live test
level and minimum privileges, never credential values.

Inspect a support bundle locally before sharing it. Remove tokens, connection
strings, internal hostnames, private schemas, sample rows and personal data.
Exports are explicit local actions; the product must not send support material
automatically. If a command is not implemented or an external qualification is
unavailable, record that exact limitation rather than a passing result.
