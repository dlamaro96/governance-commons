# ADR0013: Dedicated protected authentication transport

Date: 2026-11-16. Status: accepted for implementation; real-service qualification and integrated rollout remain open. Extends [ADR0012](0012-isolate-protected-session-provenance.md) and adopts the [broker/session contract](../execution/PROTECTED_BROKER_CONTRACT.md).

The existing application combines identity callbacks, legacy sessions and content APIs under a broad application database role. The inactive SQL012 foundation provides finite native authentication capabilities, but those capabilities need an HTTP boundary that cannot accidentally fall through to legacy session resolution or content access.

Use three small processes with the existing pinned dependencies: a fixed-route Node HTTP edge, a dedicated OIDC login broker and a dedicated session service. Each backend receives only its own native database credential. The edge has no database or identity secret. Exact public origin, Host, upstream routes and issuer endpoints are deployment configuration; client-controlled forwarded headers cannot select them. The broker commits attempt consumption before token exchange and commits session issuance before setting browser cookies. The session service independently inspects, selects and revokes through its finite native functions. No descriptor is converted into a legacy Principal.

Use one original20-second HTTP deadline across request receipt and upstream work, bounded request admission, fixed pool limits and native database timeouts. Do not retry mutations after uncertain commit. A logout request with valid origin, CSRF framing and closed body clears browser credentials even if server revocation cannot be confirmed; its response distinguishes those outcomes. Failed admission does not clear someone else's cookies.

Production requires HTTPS and host-only Secure `__Host-` cookies at `/`, plus a distinct identity hostname or separately qualified cookie-stripping boundary. Nonproduction requires exact loopback HTTP and its separate host-only `/authn` cookie family. Localhost ports alone do not partition cookies. No mode accepts both families, and the edge isolates protected cookies from existing application routes.

Qualify the new transport first in a fresh Compose project on application4314/identity4315, with exact canonical synthetic issuers and independent private credentials. Reuse cached pinned images and bind the precise candidate source; enforce capacity limits and preserve preexisting resources. A private explicit installation batch persists13 closed manifests with a single fixed24-hour expiry before execution. Replaying that exact batch is permitted; ordinary bootstrap/seed, silent renewal and automatic reactivation are not.

This deliberately adds process and operational complexity to keep authentication provenance separate from the old content role. The immediate lifecycle page supplies real sign-in, tenant selection and logout for qualification, with no content grant. Integrated core routing, TLS deployment, full authority administration, canonical policy discovery, SQL/OpenSearch equivalence, service effects and the atomic all-ingress cutover remain required subsequent work. Passing this transport gate alone cannot qualify a complete capability, deployment profile or release.
