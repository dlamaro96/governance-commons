## Pre-publication implementation refinements

The first executable review exposed omitted identity facts. The adopted fact descriptor additionally includes the exact `groupPartition: PrincipalGroups`, slot-sorted `ceilings: {slot,kind,record}[]` and `journalOperation: OperationEvidence|null`. An unavailable group partition must hash differently from a known empty partition; changing the required ACL/creator or the journal operation's actor/currentness must change identity. Ceiling records resolve only through the exact registered adapter slots. The frozen candidate remains unchanged; these explicit refinements govern the first published implementation.

Issuer, field and sensitive-field dependencies use separately subject/request-bound context records where their requests differ. Known/unavailable status must agree, and selected records must have the same semantic value, kind, state, validity and full producer/source provenance. Each context still validates its own exact subject/request/containment; a favorable alternative purpose or environment is not interchangeable. Guards alone retain the existing exact-origin FactRef remap. Identity set ordering uses the lexical canonical identity keys, including `id@version`; this is representation ordering, never newest-version selection.

For proposed/original operations, a live issuer context retains the actual command actor. It proves the exact shared operation through reciprocal consuming ChainLinks, including guard-origin traversal, instead of falsely requiring every issuer to be the command actor. Separate noncurrent scope anchors must resolve the same protected operation and exact member/side/resource/revision/security/path as their consuming context; current anchors require a null operation. Protected storage still authenticates the complete plan. A retired group with a live or future membership is a well-shaped inconsistency and produces indeterminate, matching retired-definition handling.

The semantic proof/fact byte subtotals count each selected registry lease issuer/producer once. The entire registry remains subject to physical admission and normalized-retention bounds. Unused registry entries cannot substitute for selected evidence. `factValidationVisits` conservatively counts JSON value nodes plus own data properties, including array length, for each used wrapper/payload and required subject/request/now tuple per actual interpreter call. These refinements do not change any declared numeric limit or establish measured runtime capacity.

Projector replay also needs an exact immutable consumption commitment. `ProjectionEventEvidence` additionally requires `requestAction: 'projection:consume'|'projection:write'` and `requestHash: Digest`; the corresponding `ServiceUse` requires `mode: 'apply'|'replay'`. Action/hash must match the exact branch and selected event. Apply requires pending state; replay requires applied state. The registered projector branch includes only this exact idempotent replay, and the future effect adapter must return its minimal stored result instead of performing a new write. An event identity or arbitrary request hash alone is insufficient. Actual producer authentication and once-only storage consumption remain separate mandatory work.

Protected visibility and creator records count in the shared proof-byte subtotal, including their complete selected contents. ACL member IDs do not become authority principals or new-group memberships for the other numeric limits. No caller may omit inconvenient ceiling contents to fit a budget.
