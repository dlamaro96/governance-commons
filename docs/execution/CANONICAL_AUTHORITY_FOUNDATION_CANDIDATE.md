# Canonical authority foundation — implementation candidate

Status: **DRAFT, NOT ADOPTED**, 2026-11-16. This is a proposed next increment, not an implementation, migration allocation, runtime verification or authorization to activate scoped content access. Root must review and adopt a separate contract before SQL or source changes. SQL001–012 and all prior evidence remain immutable. The complete `BUILD_SPEC.md`, especially SYS-SEC-001/002/005 and ACC-001–008, remains governing; an inactive foundation does not complete those requirements.

## 1. Concrete increment and trust boundary

Implement persistent, independently validated human authority records and a complete, session-bound **candidate graph loader**. Its result is canonical evidence for later decision assembly, not a `DecisionBundle`, a policy result, a command capability or an HTTP projection. It deliberately does not invent content containment, visibility, field prerequisites, approved facts, operation scopes or service companions. Every existing pure predicate and service branch remains required and implemented in the pure engine; their real producers remain separate work.

The first increment has these exact operational boundaries:

- A new private `gc_authority` schema, owned by the native migration owner, contains the records below. Every tenant table uses forced RLS and composite tenant keys/FKs. PUBLIC, gc_app, gc_authn_login, gc_authn_api and all existing site/projector/workflow roles have no schema usage, table/column/sequence access or function execution. There is no new application pool or HTTP route.
- All finite installation/read functions are **native-owner-only**: original `session_user` OID/name and current database OID must equal the immutable SQL012 installation root; no SET ROLE, supplied OID, GUC, role label or numeric generation substitutes. Read functions additionally require an actually broker-issued protected session. The owner is the deployment trust root, not an adversary these functions claim to constrain.
- Production/shared databases initialize empty authority definitions/grants. No general owner grant-import API ships. Synthetic native qualification inserts exact fixtures through the owner connection, using the same tables, constraints and lifecycle triggers; fixture writes are not presented as administered grants, installation consent or verified audit events.
- Only `inactive` is representable in this foundation. No mode switch, content grant, ordinary administration adapter, recovery shortcut, legacy permission import or compatibility grant conversion exists here. A future activation contract must account for every supported existing identity, permission and service principal without deletion, rescoping or silent narrowing.
- SQL012 role safety remains unchanged. Its API executor can call only inspect/select/revoke. A future content-authority executor will be a separate native registered role with exact generation and adapter privileges; **do not grant this loader to that role**. Runtime `gc_authority_read` must eventually return only its registered authorized projection, not this private graph. An SQL-enforced adapter may compose private selection helpers internally after its own closed contract is adopted.

This narrows the storage candidate's prerequisite list only for this inactive, non-runtime foundation. It does not adopt the unfinished `unknown` preparation/effect/result envelopes or authorize generic `apply(jsonb)`.

Proposed refinement requiring explicit root adoption: **issuance pins and mutable lifecycle versions are separate**. A grant, direct membership or elevation-use has an immutable issuance pin `(id, issuance_version=1)` and a lifecycle `head_version` starting at1. Revocation increments only its head version and changes current state; it does not alter an immutable child parent pin. Loader `GrantRef.version`, membership `ref.version` and elevation-use `version` mean issuance version; current `state` comes from the joined current head. The complete head-version inventory participates in the snapshot digest. Expected versions on future administration mutations mean head versions. Thus a parent revoked at head2 is returned as the original exact pin with `state:'revoked'`; loading historical creation state cannot revive its child. No restoration or in-place amendment exists; replacement requires a new ID. Definition publication retains separate head/definition versions as already proposed. In pure `DefinitionEvidence` and `PolicyEvidence`, `currentHeadVersion` maps exactly to `definition_heads.definition_version`, the latest published immutable definition version; it never maps to lifecycle `head_version`. The separately returned `LifecycleHead.headVersion` is that lifecycle `head_version`, so retirement can advance lifecycle history without inventing a new published definition. This resolves a concrete cross-record ambiguity without modifying the frozen pure engine.

## 3. SQL conventions and bounded closed values

All UUIDs are canonical non-nil values; counters use positive PostgreSQL bigint with explicit exhaustion refusal and decimal-string JSON encoding, never floating-point conversion. Head/definition/issuance versions use positive int4 and refuse overflow. In the tables below, `timestamp` always means PostgreSQL timestamptz, never timestamp without time zone. UTC timestamps have millisecond precision, years1–9999, and use half-open validity `[not_before, expires_at)` with nullable endpoints and strict ordering when both are present. Text rejects invalid Unicode and controls. Digests are lowercase64-hex SHA256. Preserve exact raw policy text separately from its canonical semantic hash.

Every nullable field is present in JSON. Reject extra keys, duplicate raw JSON keys, unknown enum variants, sparse arrays and malformed nested objects before storage. Reuse the exact adopted `PolicyDefinition`, `Scope`, `EffectCeiling`, `DelegableCeiling`, `ControlCeiling`, `AuthorityDecisionRegistry` and human `AuthorityGrant` schemas by reference; these are closed schemas, not permission to accept arbitrary JSONB. SQL independently enforces their complete grammar, finite action/kind/field membership, canonical hashes, required arrays and depth/byte limits. A matching caller digest is never enough. Canonical policy bytes/hash must match `decisionHash`/existing policy canonicalization, with executable Unicode/number/order vectors in both languages.

`scope` is stored as columns `(scope_kind, scope_tenant_id, domain_id, include_descendants, resource_kind, resource_id)`: tenant requires only tenant ID; domain additionally requires domain ID and boolean include-descendants; resource requires resource kind/ID. All irrelevant columns are null. The scope tenant equals the enclosing tenant. Scope shape is not a claim that a selected content resource exists or lies in that scope; the full adapter later proves canonical containment.

The following bounded JSON columns have only their named schemas: `effect_ceiling` = EffectCeiling; `delegable_ceiling` = null|DelegableCeiling; `control_ceiling` = null|ControlCeiling; `registry_document` = exact AuthorityDecisionRegistry; `policy_document` = exact PolicyDefinition raw text. For raw JSON use a bounded duplicate-preserving parse (for example PostgreSQL json with recursive json_each/array traversal), checking duplicate names, depth, nodes and exact scalar grammar before any JSONB conversion; text::jsonb alone is insufficient. No stored generic assertion, claimed allow, current Principal or caller-authored candidate array exists. Normalize pin/parent/membership associations into FK tables, even when a corresponding public pure DTO embeds them.

## 4. Physical records, keys and invariants

Column lists below are exhaustive apart from explicitly inherited common columns. Repeated column names without a repeated type inherit that exact previously declared type; IDs are uuid and versions are int4 unless explicitly declared otherwise. `T` means `tenant_id uuid NOT NULL`. `H` means `head_version int NOT NULL`, `state` from the table's declared enum, `changed_at timestamptz NOT NULL`. Tenant FKs include T; no UUID-only cross-tenant association. All creation/issuance bodies are immutable. Head transitions have append-only revisions with exact previous/new head versions; all child writes and head/revision consistency are checked by initially deferred constraint triggers at commit. A runtime caller has no way to disable triggers or alter a table owner.

## 8. Conservative complete selection algorithm

Implement the following fixed-point algorithm in the original snapshot; the database derives the sets. A first-N array, application-provided candidate list or policy-condition predicate is forbidden.

1. Resolve the bridge, tenant head and exact registry. For each requested atomic root, create a partition for the root identity. Record database asOf once; all validity comparisons use this asOf, while expiry/deadline checks also use clock_timestamp at every bounded phase.
2. For each distinct required human subject, read its exact canonical identity/member heads and current rows. Enumerate **all active current-or-future direct authority group memberships** whose expiry is null or greater than asOf, regardless of policy references or membership notBefore. Include a retired group if such an inconsistent membership exists; do not erase it. Pure evaluation must then fail closed. Known empty means this complete query actually returned no membership. Missing/corrupt revision provenance is a loader integrity error, not known empty.
3. Select every non-revoked, not-definitely-expired terminal grant whose beneficiary is that human or one of those groups and whose immutable effect ceiling can include the requested action/resource kind/field. Include future notBefore grants and inactive/retired dependency heads. Also include any terminal grant whose resolved full root policy set contains a resource-wide intent for the requested resource kind, even if its ordinary action comparison would exclude it. Never filter using rule effect, `when`, current matching allow, approved facts, root role membership, issuer liveness or an early deny. Scope is **not filtered** here: current/proposed/original containment is not yet produced, so every otherwise relevant scope is retained as a conservative superset.
4. An excluded terminal is excluded only by proved beneficiary disconnection, explicit canonical revocation, definite expiry (`expiresAt<=asOf`), or a literal ceiling/action/kind/field disjointness with no applicable resource-wide intent. Query every qualifying row under the same snapshot; database cardinality/byte preflight before fetching payload proves the set fits. Never choose an arbitrary subset that fits. Retired policy/role/type/group heads do not justify exclusion.
5. For each selected terminal, follow **every exact stored parent** to its ordinary-role or responsibility origin. Retain referenced parents and via-memberships even if revoked, expired, future or inconsistent. Retain full root role/type pin and **every policy pin** in that definition, not only rules matching this request. Null-mapped responsibility remains visible as a documentation-only origin and cannot manufacture an effective binding. Structural missing references, cycles, mismatched mappings, duplicate overlapping memberships or impossible parent kind fail the whole load; current inactive evidence is returned faithfully.
6. For each connected delegation/elevation edge, add the issuer's same-AtomicRequest partition and recursively perform2–5. A human ordinary issuer is historical attribution and does not cause an unnecessary live issuer-decision partition. Record `ClosureDependency` for every consuming partition/child/issuer occurrence. A complete union exceeding the bound refuses with the explicit conservative profile limitation below, not a tenant-population cap or an assertion that production capacity is qualified. Retired group contradictions remain observable.
8. Materialize after preflight, independently recompute definitions/registry/companion hashes, compare normalized FK-derived mappings to stored envelopes, and check the output counts against preflight.
