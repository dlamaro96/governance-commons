## Frozen pure behavior

- `compatibilityActions(permissions)` returns a deterministic finite list of the exact compatible IDs whose original all-of permission predicate holds. Empty permission membership receives only the four explicitly declared active-member baseline actions; authentication/activity is a separate mandatory caller ceiling. Unknown/duplicate or malformed permission input throws a typed TypeError/RangeError instead of broadening scope; the function returns an action array only on success. No ADMIN,FIELD or SERVICE action is mapped automatically. This pure mapping does not install grants or authenticate a member.
- `parsePolicy(input, catalog?)` and `parsePolicyFile(text, catalog?)` return the declared discriminated `Parsed<PolicyDefinition>` result and bounded submitted-input-only issues. Default catalog has no registered field IDs. The optional catalog is a trusted immutable list of exact registered field strings supplied by a future protected registry adapter, never a client-authored list. Copy and descriptor-validate it before lookup. The readonly string array has at most 16,384 unique entries and 128 KiB total UTF-8 field bytes; each field is nonempty, valid Unicode and at most 256 UTF-8 bytes. Reject duplicates/accessors rather than truncating. These are a caller-supplied relevant trusted catalog, not global registry enumeration. Tests may explicitly supply a small synthetic catalog. It proves syntax/catalog membership only, not permission or provenance.
- Enforce 64 KiB UTF-8 raw and canonical normalized policy size; 128 cumulative expression nodes across all rules; depth 8 with root depth 1; nonempty maximum 128 rules; nonempty maximum 256 finite sets/children;unique rule IDs and set members;valid canonical lowercase UUIDs;positive safe versions within existing PostgreSQL integer bounds;canonical millisecond UTC;half-open valid intervals. Bound issue output to the first 64 deterministic issues and hostile JS object traversal before materialization. No getter invocation, symbols, exotic/inherited objects, cycles, malformed Unicode, nonfinite/unsafe numbers or unsupported values may be silently copied or accepted.
- All grammar objects reject unknown/missing properties. Reject duplicate JSON object keys before ordinary JSON materialization. Reuse a proven existing bounded parser only where its exact limits and behavior satisfy this contract; otherwise write a narrowly scoped strict parser without a new dependency. Unknown actions/resource kinds/operators fail closed. All 136 registered actions are valid syntax; mixed human/service non-field action arrays are not rejected solely for mixing, because grant/activation provenance is a separate mandatory future boundary. `fields:null` permits only the closed non-field actions; nonempty registered fields permit only FIELD actions. Resource-wide intent is a separate future protected companion, never inferred from null.
- Normalize only declared sets using exact scalar/tuple comparators; preserve rule order and all/any child order. The parser returns a fresh safe value without mutating input. Export a deterministic canonical serialization/hash only using a documented project-compatible implementation and test it against independent known vectors. Do not pretend TypeScript normalization establishes SQL equivalence; that future gate remains unrun.
- The AST vocabulary includes purpose/environment/classification predicates. Parsing them is not publication or activation; live provenance adapters and negative runtime gates remain required. No policy evaluation or decision/lease minting is part of this increment.

## Input admission refinement after independent review

External policy adapters must call `parsePolicyFile` while the document is still raw text; its 65,536-byte UTF-8 admission check runs before JSON materialization. The in-memory `parsePolicy`, canonicalization/hash helpers, field catalog and permission-array mapping require trusted caller admission. They still reject proxies, accessors, unknown/non-enumerable/symbol keys and malformed data, but exact own-key rejection uses reflection whose cost scales with the preexisting caller object's keys. Standard JavaScript reflection cannot guarantee bounded enumeration of an arbitrarily large already-materialized object; `for-in` would also miss symbols/non-enumerables and may snapshot keys internally. The earlier hostile-traversal bound applies to admitted JSON data, not arbitrary unbounded object metadata. This reviewed clarification introduces no runtime adapter or activated ingress. Future adapters must prove raw-body and trusted-loader admission before authority activation.
