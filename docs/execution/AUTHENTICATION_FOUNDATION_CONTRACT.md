## Exact adoption refinements

1. Use detached private sessions exactly as ADR0012 requires. The new tenant mode can only be `inactive`. No legacy session dual-write, retrospective certification, caller-supplied allow result or generic evidence reader is permitted. Installation and session events remain private, typed infrastructure records; safe audit projection and retention are separate required work.
2. `executor_registrations` explicitly includes non-null `channel_id uuid`. Its reference key is `UNIQUE(id,kind,channel_id,generation)`. Generation heads use the corresponding four-column FK. All runtime registrations have `rolreplication=false` in addition to the candidate's safe flags, exact original login OID/name and empty membership adjacency. Check these attributes at provisioning and use. Prepared transactions must be disabled for this inactive profile; role flags alone do not prove that condition.
3. `registration_revocations` has concrete nullable `executor_registration_id`, `issuer_registration_id` and `identity_binding_id` FKs. Exactly one is non-null and matches `target_kind` and `target_id`; each typed target is unique. The target record, monotone revoked timestamp and immutable receipt must agree. No unvalidated polymorphic target is accepted.
4. A manifest's `operation` is a closed object with discriminant `type`, one of the nine exact operation names. Its remaining fields are exactly the candidate's operation-specific list. `kind` inside register/advance executor operations remains `login|api`. Common fields are exactly the candidate's eight named fields. Reject unknown keys, missing/null values outside declared nullable positions, duplicate raw JSON keys and oversized input before retained materialization. OIDs are positive unsigned32-bit integers; versions/generations/epochs remain positive signed32-bit integers. UUIDs are canonical non-nil lowercase values. No implicit type coercion.
5. Freeze the receipt codec as follows. Encode UTF-8 prefix `gc-authn-install/v1;`, then the operation name using the string scalar encoding, then each **SQL signature argument name in the documented order**, encoded as a string scalar, immediately followed by its typed value. String is `S<UTF-8-byte-length>:<value>`; null is `N;`; integer/OID is `I<base10>;`; UUID is `U<canonical>;`; timestamp is `T<canonical-UTC-milliseconds>;`. There are no additional separators, optional tail, generated receipt ID, generated current time or implicit resolved fields. Hash these bytes with SHA-256. The storage implementation independently checks actual database/owner/role OIDs equal the supplied expected values and resolves every referenced immutable registration and canonical tuple. Input hash equality is never authority proof. The private receipt retains the exact encoding for recomputation after later head changes. The tool and SQL must agree byte for byte, including multibyte strings and nulls. `predecessorManifestHash`, when non-null, must identify a prior immutable receipt in this installation; make receipt manifest hashes unique and enforce the self-FK.
6. Preserve the exact legacy privilege boundary using the [frozen census](authentication-legacy-function-census.json), SHA256 `a2affa4c201bd03c23bdf91ed7f765fcbcde0cb3c351c13607be405ba3cfb51e`:155 existing public `gc_*` signatures,56 with PUBLIC execution. Freeze literal signature statements to remove those56 PUBLIC grants and give gc_app the same effective execution it previously had. All155 effective gc_app outcomes must remain unchanged. Do not grant any new protected function to gc_app. The authentication definer receives only `gc_tenant()` and `gc_actor()` among those legacy functions for existing membership RLS. The census is read-only observed metadata, not SQL012 qualification.
7. Keep SELECT-only canonical identity/member privileges on the authentication definer. Only the two private owner lock helpers may lock those exact resolved rows, with forced RLS, explicit predicates, no data return or mutation and no runtime EXECUTE grant. Follow the candidate's configuration/head → fence → identity → membership → authentication row order. Owner tenant-generation advancement takes the tenant ledger before those locks. Inspector stays nonlocking and must work in a fresh READ ONLY REPEATABLE READ transaction. Mutations reject incompatible isolation and recheck state/time after waits. All derived GUCs restore on success and failure.
8. Require an immutable consumed transaction ID and a different transaction for issuance. This proves visible committed consumption; it does not make SQL autonomous or prove an external OIDC exchange. Broker commit-before-exchange remains a separate future transport obligation. Require verified auth_time and strict auth_time ≤ iat ≤ database clock; retain the candidate's lower-bound allowance and exact attempt/session lifetimes. No renewal, synthetic authentication time or token material in logs/evidence/workflow payloads.
9. The installation tool and SQL independently accept the same bounded endpoint grammar, without normalization. Validate issuer and redirect separately. Require explicit lowercase `https://`, or `http://` only in a non-production environment with exact host `localhost`, `127.0.0.1` or `[::1]`. Accept ASCII lowercase DNS labels of1–63 characters, alphanumeric with internal hyphens only, total host length≤253; the final DNS label starts with a letter. IPv4 is exactly four decimal octets0–255 without leading zeros. The foundation's sole bracketed IPv6 spelling is `[::1]`; broader IPv6 support is unqualified. Optional ports are decimal1–65535 without leading zeros. An optional path starts `/`, followed optionally by `?query`; a query without a path is allowed. Path/query characters are RFC3986 ASCII unreserved characters, sub-delimiters, `:`, `@`, `/` and `?`; each percent sign must start exactly two hexadecimal digits. Reject userinfo, fragments, whitespace, control bytes, backslashes and non-ASCII input. Preserve the admitted raw string byte for byte. This corrects the original prefix-only SQL check and permits a configured HTTPS issuer with a local HTTP callback in non-production. It does not qualify network reachability, OIDC discovery or an external issuer.

10. Retain the qualification plan's legacy session-hash collision refusal as a bounded additional check. A private owner SECURITY DEFINER helper may return only whether the exact submitted hash exists in `public.sessions`; grant its execution only to the authentication definer and owner. It supplies no legacy row, tenant, identity, read/write grant or runtime enumeration endpoint. Issuance rejects an already observed collision. This point-in-time guard neither attaches provenance to legacy rows nor establishes atomic uniqueness against later independent legacy writes; detached storage and the future separate cookie remain the trust boundary.
