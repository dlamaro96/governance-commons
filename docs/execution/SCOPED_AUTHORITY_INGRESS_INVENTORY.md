## 1. Existing vocabulary and identity boundaries

There are ten current human membership permission strings in the inspected application and storage checks:

| Alias used below | Exact existing string |
|---|---|
| CR / CW | `catalog:read` / `catalog:write` |
| SR / SW | `sources:read` / `sources:write` |
| AR | `audit:read` |
| MR / MW | `models:read` / `models:write` |
| DR / DW / DA | `domains:read` / `domains:write` / `domains:assign` |

`+` means **all** listed permissions, never any one. These strings are compatibility inputs, not the proposed final authority engine. Membership `role`, display names, owner IDs, type labels and source-authored metadata are not grants. Audit action strings (`asset.updated`, `relation_migration.executed`, `domain.moved`, etc.), idempotency operation strings (`source.scan`, `relation-migration.execute`, `domain.placement`, etc.), workflow names and SQL operation kinds are separate namespaces; do not accidentally accept them as policy actions.

| Current resource identity | Proposed typed authority reference and ceiling |
|---|---|
| Tenant UUID; global identity UUID; `(tenant, identity)` membership | `tenant`, `tenant-member`. Global OIDC identity/session administration is not tenant content authority. An active tenant membership remains required for human decisions. |
| Session hash; OIDC login-state hash | Authentication state, never an authority resource ID or a public grant target. Tenant switching selects an already active membership. |
| Source `(tenant, source UUID)`; job `(tenant, job UUID)` with source and initiating actor | `source`, `scan-job`; resolve the source from the canonical job, not caller-supplied job/source association. Source secret references are not credentials. |
| Asset `(tenant, asset UUID)` and `(tenant, asset UUID, revision)` | `asset`; history uses an exact revision plus protected original references. Retain current identity ACL (`tenant` visibility or identity allowlist), source association and native restrictions as ceilings. Ownership is descriptive. |
| Flat model `(tenant, text model key)`; authored type additionally has immutable UUID `governance_models.type_id` | `model-definition` and `asset-type`. **Resolve the UUID-only draft mismatch before implementation:** create a protected additive mapping from existing flat-model keys to authority UUIDs, or adopt a validated discriminated non-UUID identity. Do not rewrite existing model keys/receipts, derive an unchecked client UUID, or conflate a model key with a type UUID. |
| Relation type has logical text `relation_types.id` and UUID `type_id`; versions pin UUID and version | `relation-type`; adapter resolves text-route keys to the canonical UUID before decisions. Definition endpoint type references are protected references too. |
| Relation UUID; participation binding UUID; original graph operation/receipt UUID; preparation UUID | `relation`, `relation-participation`, `relation-operation`, `relation-preparation`. Relations require the edge and both endpoints. Participation additionally binds its asset/type and linked complete operation. Preparation remains creator-only with its original expiry. |
| Domain-type UUID plus logical key; domain UUID; placement keyed by asset UUID and independent placement version; domain migration UUID | Keep exact existing event kinds `domain-type`, `domain`, `asset-domain-placement`, `domain-type-migration` in the adapter. Domain placement is not an asset revision. Domain is not tenant/workspace. |
| Audit `(tenant, audit UUID, sequence)`; outbox `(tenant, event UUID)`; idempotency `(tenant, actor, operation, key)` | Audit decisions resolve exact event family + typed original resource. Outbox/idempotency are protected infrastructure records, not ordinary content that a grant holder may arbitrarily author. A known key or stored allow cannot grant present disclosure. |
| Configured site/worker tokens, `SITE_TENANTS`, secret-file entry and local source target | Existing service boundary, not a canonical rotating service-principal/lease implementation. A1 needs explicit service/source/tenant bindings; do not convert these into human grants. |

Every resource reference includes tenant and kind. Equal UUIDs in different tables must never alias. New create operations authorize the destination tenant/parent and canonical referenced resources before the new UUID exists; a caller cannot register a free authority object. Versioned policy/receipt objects use exact versions, not only current heads.

## 2. Proposed closed A1 action registry

The following action IDs are **proposed**, not existing runtime constants. They form a finite current-surface registry: expand each comma-separated ID literally; there is no wildcard, prefix grant or automatic grant for a future action. Each row specifies the exact legacy eligibility predicate and current resource ceiling. A compatibility grant is produced only from actual current active membership state. The permission predicate alone never removes the resource ceiling or operation-specific invariant.

### Sources, audit and operation responses

| Proposed IDs | Existing ingress and eligibility | Resource/egress boundary |
|---|---|---|
| `source:discover`, `source:configuration.read`, `scan-job:discover`, `scan-job:read` | Source/job lists and job detail: SR | Canonical source/job; configuration includes the existing secret reference, never the secret. Jobs do not require requester ownership today. |
| `source:create`, `source:scan.request` | Create source and POST scans: SW | Exact destination/source, bounded configuration and idempotency. There is no general source edit/delete endpoint to grant by inference. |
| `audit:event.read` | `/audit`, asset embedded audit and overview recent audit: AR plus family-specific predicates below | Audit events and every disclosed resource reference; source/model/type generic families currently differ from asset/relation families. |
| `audit:chain.verify` | `/audit/integrity`: AR and complete visible audit scope | All entries must be authorized before full-chain verification; preserve the 10,000-entry development bound and generic hidden-scope refusal. |

Operation results and replays are action-specific egress, not free-standing broad discovery rights. SW can currently create/scan and receive its source/job result without SR. Domain creation can return its pinned type reference without MR. Asset `assetView` already returns attributes/model pins/type state with CR, although dedicated attributes/type-state routes additionally require MR. Preserve these existing differences in the compatibility table and explicit field obligations; do not silently grant SR/MR to make a uniform adapter convenient. Any intentional restriction is an explicit separately reviewed policy change. A field deny must nevertheless cover **all** these egress paths, search text, historical inspection and operation results; otherwise the stricter endpoint is bypassable through another projection.

Proposed A1 field actions are `field:read` and `field:sensitive.read`, bound to an already authorized typed resource, declared projection and finite trusted field IDs. `field:read` compatibility covers only fields disclosed by that exact existing action/route; it is never an independent discover/read grant or permission for future fields. `field:sensitive.read` has no automatic legacy mapping: sensitivity facts and explicit grants need an adopted impact/activation plan. The evaluator, field projections and all current egress adapters must implement this distinction in A1. This is required implementation with separate activation, not deferred sensitive-field enforcement.
