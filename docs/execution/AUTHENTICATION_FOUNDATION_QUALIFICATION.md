# Inactive authentication foundation: real PostgreSQL qualification design

Status: VERIFICATION DESIGN / NOT EXECUTED. Recorded 2026-11-16. Private engineering handoff; no source, DDL, role, runtime, Git, requirement or release status change. Root must adopt the final protocol and this execution profile before implementation/execution. SQL001–011 and all previous evidence remain immutable. The planned namespace is `gc_authn`; a migration number is intentionally not allocated here.

## Required scope and trust boundary

This increment can qualify provisioned executor/issuer identity, one-use broker attempts, detached private sessions and their immutable provenance, inactive tenant fences, actual PostgreSQL privilege boundaries and concurrency. It cannot qualify OIDC signature validation, HTTP cookies/CSRF transport, the complete policy loader/evaluator, service claims/leases, administration, or atomic all-ingress activation. Those remain required later. Relevant parent requirements are SYS-SEC-001/002/003/006, SYS-SEC-004's future credential boundary and OSS-007's honest qualification; none becomes a broad PASS from this gate.

The drafter's selected tables are global installation_receipts, executor_registrations, generation_heads, issuer_registrations, identity_bindings, login_attempts, attempt_consumptions, sessions, session_provenance, session_events; only tenant_fences is tenant data with forced RLS and an inactive-only mode. Global authentication tables still need explicit executor/identity/tenant-tuple checks and no runtime enumeration. Cross-tenant private sessions do not imply cross-tenant content authority. The six proposed public functions are gc_authn_attempt_begin/consume/session_issue/session_inspect/session_revoke/session_select; use final adopted typed signatures, not a generic JSON dispatcher. Owner-only typed installation is separate from runtime functions.

Detached private sessions are essential: legacy public.sessions has mutable rows and raw CSRF material, and gc_app can directly insert/update/delete it (001:5,31–34; security.ts:15–25,60,63). There is no dual write, public.sessions FK or retrospective certification. Private issuance refuses an existing legacy hash collision, but private validation never uses a legacy row as authority. New API/broker credentials must not inherit gc_app or PUBLIC legacy function access.

## Proposed new low-disk execution profile

Do not alter the existing two-GiB floors or reinterpret their historical results. A separately named `authn-foundation-tmpfs` profile can be feasible, subject to root adoption and fresh admission checks:

* Reuse exact already-present image IDs, `--pull never`, no build/install/download, no named/anonymous volume, no Compose changes, no host published ports. PostgreSQL runs `--network none`; one helper at a time joins its network namespace. Both root filesystems are read-only and both log drivers are `none`.
* PostgreSQL: memory512MiB, memory-swap512MiB, CPU1, pids128, cap-drop ALL, no-new-privileges, user `postgres`. Mount tmpfs `/var/lib/postgresql/data`256MiB mode1777, `/tmp`16MiB mode1777, `/var/run/postgresql`4MiB mode1777. Set PGDATA to the child `/var/lib/postgresql/data/pgdata` created by postgres; do not place the data directory at the writable-root mount itself. Verify mount type/size and no anonymous volumes after start. Use shared_buffers32MiB, work_mem2MiB, maintenance_work_mem16MiB, max_connections16, min_wal_size32MiB/max_wal_size64MiB, max_prepared_transactions0, fsync/full_page_writes/synchronous_commit ON. The profile fails if these limits cannot hold the real predecessor fixtures; it never disables durability or silently shrinks the fixture.
* A shell entrypoint under the postgres user can execute installed `initdb --auth-local=trust --auth-host=scram-sha-256`, then exec postgres. Local Unix trust is confined to the isolated container for deployment bootstrap; every executor assertion must be a native TCP connection with a distinct random SCRAM password. The runner cannot mount the database/socket; it sees only loopback TCP. The initial bootstrap admin sets passwords through private stdin/parameterized SQL, not shell arguments or a public report. No POSTGRES_HOST_AUTH_METHOD=trust for TCP. This launch recipe is a proposal, not an executed compatibility result.
* The one helper has memory384MiB, memory-swap384MiB, CPU1, pids128, read-only root, cap-drop ALL, no-new-privileges, log-driver none and `/tmp`32MiB tmpfs. Mount only frozen source/tests read-only. Run the existing Node24/pg/tsx/migrator from the cached app image, with exact dependency-manifest equivalence checked first. Use the helper's private stdin or a bounded tmpfs configuration for random fixture credentials; do not print URLs/hashes. If 384MiB is insufficient, fail and request explicit profile revision rather than build or enlarge silently.
* Combined hard container memory ceilings are896MiB; all tmpfs storage counts within those ceilings, not an extra disk allocation. At admission, Docker reports7.654GiB total RAM and all10 currently running containers sum about2.89GiB working usage. Reserve at least1GiB for daemon/VM/unmeasured growth and require at least2GiB observed headroom before starting. The observation is not an RSS/cgroup-cache or host-swap guarantee. Check aggregate usage again between phases; stop only this run's containers if pressure exceeds the adopted bound. Container memory-swap equality prevents additional container swap but cannot promise the macOS VM never swaps.
* Fresh host floor1GiB, maximum total new host output100MiB (including private logs, source snapshots, temporary files and reports), maximum individual captured diagnostic4MiB; bounded streaming writes, no unbounded subprocess capture or Docker logs. At the observed1.378GiB free, the full100MiB output cap still leaves about287MiB above the1GiB floor. Recheck free bytes before each phase and while collecting output; fail at the floor or output cap, retain a small bounded failure record and clean up only owned containers. Existing evidence is never deleted. Docker metadata/daemon allocation is not strictly capped by this script, so this admission is conditional, not a disk guarantee.
* Use unique run labels/names, track every helper PID/container, retain starting image/container/volume identities, prohibit concurrent heavy work, remove only positively owned helpers then the owned PG instance in finally. Require zero residual owned containers and unchanged preexisting image/container/volume inventory before PASS. An externally killed harness cannot promise finally ran; a RUNNING report and exact labels must support a separately reviewed recovery/readback. No global prune and no unrelated local projects operations.

Read-only inventory: PostgreSQL image `sha256:839fbb5a4942a7758dd93e18b42ea5649807491a0545b5eeeb8f0b8bb11857a5`, app image `sha256:b56f057bc8adf068b8541ff2cdef2dfda014c41ee8f63a8f98415d045f4d04ef`; Docker27.3.1, arm64. ## Concrete test suites and assertions

Suggested new files after adoption: scripts/runtime-test-authority-authn-foundation.py; dedicated tests/qualification/authority-authn-foundation-storage.test.ts and authority-authn-foundation-concurrency.test.ts; a synthetic fixture module. Names are proposals, not files created by this plan. Keep privileged role provisioning outside migration-owner execution, and use native separate login pools for every assertion. Test failures must include safe SQLSTATE/operation labels, not session hashes, CSRF hashes, verifiers, tokens or passwords.

### 1. Forward upgrade and preservation

1. Execute the actual checksum migrator on exact001–011 under a non-superuser, non-BYPASSRLS, NOCREATEROLE owner. Seed representative legacy identities/memberships (including inactive/revoked permissions), sessions/login states, canonical assets and immutable revisions, typed/graph/domain receipts, audit/outbox/idempotency. Capture every original row's complete JSON bytes and count; compare by original primary key afterward, so deletions cannot disappear from a filtered comparison.
2. Preprovision only the final closed roles and required memberships through the disposable deployment admin, then apply the forward migration under the real migration owner. Assert exact checksums and prior applied_at values; replay the migrator and compare all installation/authn records and all legacy rows. No regrant, reactivation, synthetic admin or credential rotation on replay.
3. In separate disposable databases, reject a changed predecessor checksum, missing prerequisite role, superuser/BYPASSRLS/login definer, unsafe membership path, wrong role owner/OID and conflicting protected namespace/installation. Assert transaction rollback leaves no partial new schema/receipt/grant and no altered baseline. Reject broad schema-default grants and unexpected existing role names rather than treating names as installation proof.
4. Confirm all tenant_fences force RLS, are inactive, and have no accepted transition to active. Runtime grants expose only the six exact adopted signatures. No policy, grant, context, command, service lease or content projection can be minted through this increment.

### 2. Native privilege and identity matrix

For old gc_app, current API/login roles, another generation, an unregistered native login, owner and definer, enumerate effective table/view/sequence/function privileges, transitive memberships, role flags, default ACLs, schema CREATE/TEMP/database rights and ownership. Exact native `session_user` OIDs must differ as provisioned. Wrong/missing password and forbidden SET ROLE into broker/owner/definer must fail. No application role owns protected tables or has BYPASSRLS/CREATEROLE.

Probe every new entrypoint from every wrong family, every legacy gc_* PUBLIC entrypoint from each new runtime role, direct private-table reads/DML, RETURNING/sequence access, unsafe search_path/temp shadowing, forged gc.actor_id/gc.tenant_id/generation/application_name and role-name impersonation. None can confer authority. In a separate disposable DB, drop/recreate a registered role with the same name and show its new OID is rejected; test a connected old generation after protected generation revocation too. Definer `current_user` must never replace original `session_user` identity. Owner is installation authority, not a runtime test substitute.

Prepared transactions need a separate server prerequisite: max_prepared_transactions=0 disables them; ordinary TEMP/CREATE revocation does not establish that prohibition. Assert the actual setting and a native PREPARE rejection in this isolated profile. Later old-executor cutover still inspects/resolves preexisting prepared transactions under a separately reviewed protocol. [PostgreSQL17 setting](https://www.postgresql.org/docs/17/runtime-config-resource.html#GUC-MAX-PREPARED-TRANSACTIONS) and [PREPARE semantics](https://www.postgresql.org/docs/17/sql-prepare-transaction.html) support this distinction.

### 3. Broker attempts and detached issuance

Use exact typed inputs and descriptor shape from the final contract. Begin derives its expiry/issuer/executor binding from DB time/configuration. Consume must match attempt/state and bound current broker role/generation; concurrent consume yields one committed winner and one denial. Wrong issuer, audience, nonce, unknown provisioned subject, inactive identity/no active membership, expired/future-invalid claim windows and unknown executor all fail without private session/provenance rows. No caller-selected actor/grants/permissions are accepted.

Issue must require exact committed consumption, one-use issuance and current provisioned identity/membership. Drafter accepted an immutable consumed_transaction_id xid8 and same-current-xid refusal: test consume→issue within one transaction denies, rollback removes consumption, then a committed consumption is visible to a different READ COMMITTED transaction. This is a later-transaction proof, not autonomous commit. Roll back consume and prove issue fails; issue twice concurrently and require one immutable issuance. A trusted broker must commit consume before external OIDC exchange: SQL cannot retract a returned verifier or prevent an external exchange after caller rollback. This gate qualifies database provenance only, not external JWT/PKCE validation or broker trustworthiness.

Legacy fake session inserts cannot pass private inspect; legacy hash collision refuses new issuance; updating/deleting unrelated or formerly colliding legacy rows cannot retarget a valid private session. New private issue adds zero public.sessions rows. Private provenance/events cannot be edited/deleted or forged by any runtime role. Bind every returned sessionId/version/identity/selectedTenant/issuer/executor/expiry field to the canonical protected row and exact recorded event; no permission arrays or content.

### 4. Session lifecycle and stateless reads

Inspect is a real READ ONLY REPEATABLE READ transaction: succeeds for one live exact session, accepts no actor assertion, performs no private writes or row locks, returns one bounded descriptor, and cannot enumerate sessions. Confirm query does not retain mutated caller GUC state beyond the adopted contract; compare before/after settings explicitly. Inspect unknown/expired/revoked/wrong-hash sessions and disabled identities/memberships uniformly without private metadata leakage.

Tenant selection requires the exact session/CSRF proof and an active canonical membership, follows principal-before-session locks, advances the exact session version and emits only its one immutable event. A supplied tenant UUID alone is not membership. Old version/tenant-bound descriptors cannot be reused by future protected operations; this foundation can only prove the session change, not future cursor adapters. Logout requires exact session/CSRF and final adopted idempotency behavior, does not delete business history and cannot revoke another session. Private sessions remain independent of later legacy session edits.

### 5. Deterministic concurrency and revocation

Use independent native PostgreSQL connections, explicit transaction barriers and pg_blocking_pids/wait-event observations (never query text with authentication literals). Assert both winner orders for attempt consume, session issue, tenant select versus membership revocation, issue versus global identity deactivation, session select versus logout, and executor/issuer revocation versus issuance. Hold the first transaction until the waiter is proved blocked; release and assert exact post-wait denial/current tuple, no orphan provenance or duplicate event. Do not use sleep duration alone as proof.

Verify global identities are locked in UUID order before memberships/authn rows; mutation holds required current activity through commit, while revocation itself never acquires a later tenant ledger after an identity lock. Session-only revoke must not invert principal ordering. Repeat unrelated tenant activity to prove no accidental global tenant-fence serialization. Test rollback releases every lock and changes no event/version. A read-only RR inspector may retain a valid old snapshot after concurrent revocation; a newly opened snapshot must reject it. Do not claim read snapshots linearize with a mutation they deliberately do not lock.

### 6. Bounds, deadlines and failure evidence

Probe adopted exact string/digest/UUID/version/time bounds and just-over-limit values, nulls, unavailable refs, wrong tuple family and oversized payloads before retained materialization. Typed SQL cannot prove rejection of duplicate raw JSON keys after JSONB parsing; later transport strict parsing remains separate. Prove the DB-derived original attempt/session lifetime is not renewed by retries, repeated inspect or nested helpers.

Pre-arm statement_timeout/lock_timeout in a separate native frontend command, then hold a conflicting row and assert SQLSTATE, bounded elapsed time and full rollback. Separately test cooperative internal clock checks. SET statement_timeout inside the executing function does not establish a hard30-second interrupt for that same outer statement (existing storage contract106); never label a mere post-work deadline check as universal interruptibility. Tests may use tightly bounded private fixtures but cannot rewrite production time or shorten actual session expiry semantics and claim an elapsed-expiry gate.

Pass requires declared tests exactly equal TAP tests, zero fail/cancel/skip/todo, all source/migration/config hashes stable, dependency/image identities matched, actual before/after rows unchanged, native role assertions true and owned containers absent. Preserve every unsuccessful attempt and original report/log digest. A test not run stays NOT_RUN, never skipped-PASS. This plan supplies no executed counts.
