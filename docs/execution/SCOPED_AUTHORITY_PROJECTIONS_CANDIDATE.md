## 1. Registry rules that can become executable contracts

Use three independently closed registries. Proposed IDs below are server-owned literal handles, never strings accepted from a caller as authority.

- `AdapterId` binds an exact ingress/command branch, primary and referenced resources, required action(s), complete-scope loader, egress `ProjectionId`, replay loader and disclosure mode. An HTTP route is only one entry point; the same adapter must be selected by direct service callers and protected SQL entry points.
- `ProjectionId` is a versioned wire schema plus a finite field-binding program. Its output includes every declared container, scalar and referenced-resource dependency. New output keys, unrecognized union arms, unregistered dynamic keys or missing provenance cannot fall through to a permissive serializer.
- `FieldId` is a stable semantic identity used with an exact canonical resource and, when applicable, immutable revision. JSON paths are implementation bindings. A rename, alias, joined label, nested receipt, before/after view or search projection does not create another permission target.

Proposed additional internal catalog record contract (for review, not implemented exports). `FieldId`, `ProjectionId`, `UUID` and `Digest` use the strict branded registry primitives in the parent contract; branding alone is insufficient without a current protected registry lookup.

```ts
type ResolverId = 'primary' | 'model-alias-pin' | 'domain-type-pin'
  | 'relation-type-pin' | 'asset-revision' | 'domain-revision'
  | 'placement-revision' | 'relation-revision' | 'participation-revision'
  | 'member-reference' | 'source-reference' | 'operation-member'
  | 'registered-attribute' | 'connector-observation' | 'complete-cohort'
  | 'submitted-file' | 'transport';
type FieldBinding = {
  output: readonly (string | { readonly each: true })[];
  field: FieldId;
  resource: ResolverId;
  revision: 'current' | 'from' | 'to' | 'recorded' | 'pinned' | 'none';
  presence: 'required' | 'optional' | 'variant';
  dependencies: readonly FieldBinding[];
};
type ProjectionRegistration = {
  id: ProjectionId;
  schemaDigest: Digest;
  mode: 'object' | 'list-item' | 'complete-scope' | 'immutable' | 'transport';
  bindings: readonly FieldBinding[];
  unknownProperty: 'deny';
};
```

Section3's finite expansion defines the proposed static FieldId membership; section4 defines protected dynamic registration membership, and section9 defines the closed resolver cases. Generate the literal static/adapter/projection catalogs and validate all bindings before implementation ownership is split. The output path is trusted schema data, never a caller-supplied policy selector; `each` iterates the actual bounded array and is not a wildcard grant. Resolver identifiers are not arbitrary property access. Every recursive expansion charges the shared original transaction's aggregate budget. Registry version/hash participates in decisions, cursors, preview consent and executor generation; unknown future registry versions fail closed.

`resource` and `revision` are mandatory parts of a field decision. A common `resource.version` field on an asset never means the placement version. A model text key resolves through the proposed protected model UUID mapping; a type UUID is an alias of that model object. Display names and UUID-looking strings do not choose a resource kind.

### Required fields, variants and mutation results

All currently emitted fields are required unless the actual TypeScript/wire schema explicitly marks them optional or a documented union branch excludes them. Nullable is not optional. Foundation `assetView`, `sourceView`, `jobView` and `auditView` always construct all their keys, despite lacking response schemas. A1 must declare strict response schemas for these existing shapes; missing schema is not authorization to silently omit fields. Domain routes already check strict response schemas before commit and serialization (`business-domains.ts:105,113`; `business-domain-http.ts:129`).

If a required field/reference is denied, deny that object. For collections, determine eligible complete objects before sorting, pagination, matching, counts and facets. Do not page first and then filter. For complete previews, mutation responses, exact receipts and integrity verification, deny the whole response/operation before disclosure; never shrink the affected cohort. A successful mutation must authorize its required result before committing the canonical effect and idempotency success, not commit and then discover that serialization must fail. Cached success is reauthorized with the original recorded scope and the current projection catalog.

Optional omission is allowed only on the declared optional branch, with a separately registered omission decision. Do not emit `null`, empty string, empty attributes, a masked literal or a fabricated zero to replace forbidden data. Existing application branches such as asset-detail `audit:[]` when AR is absent and overview source/job counts of zero without SR are explicit legacy compatibility behaviors; they are not a general redaction mechanism. The implementation must preserve these exact branches or adopt a separately versioned intentional change. Existing hash-bearing canonical documents are never redacted or rehashed into an allegedly original receipt.

### Adopted narrow reference disclosure; protected resource-wide intent

The design selects explicit adapter-bound narrow reference disclosure for the existing compatibility predicates. It derives only from an authorized parent action and exact registered projection; it grants no general SR, MR, member discovery or `*:reference.read` action. A missing unrelated general-read allow does not deny this intentionally narrower projection. An action-specific deny for a different general-read action need not veto it. Explicit field/sensitivity denies and **resource-wide deny intent always veto it**, through aliases and registered dynamic fields as well as ordinary fields.

The earlier candidate's non-field-action-only expansion is insufficient. Proposed adopted correction: persist a protected resource-wide intent marker, naming its actual policy/rule/grant provenance, exact scope, registry version and validity. Evaluate that intent against every canonical projection/reference, in addition to the finite expanded operation actions. It is not a runtime `*` action or caller-set flag. A new field/action/alias/projection requires the pinned-registry forward-impact gate before activation; it cannot slip between old expansion lists. Resource-wide intent on one canonical model object covers both model/type aliases. Ordinary action-specific denies remain ordinary action-specific rules.

The protected reference-evidence tuple must contain: parent decision/context ID; actor/service and tenant; exact parent action and primary resource/revision; adapter ID; projection ID/schema digest/catalog version; trusted resolver ID and reference role; exact target canonical kind/UUID/revision; sorted finite field IDs and their digest; source reference provenance (canonical row/revision/receipt companion and hash); target security/classification version; subject/membership and policy/grant versions; authority generation/epoch; original transaction/backend/request hash; original deadline and earliest validity expiry. The target tuple/fields are derived from locked canonical facts, never accepted from submitted labels, arbitrary JSON paths or an old cached result. SQL and the service independently prove the parent binding, exact reference and deny checks. This evidence cannot be reused by another adapter, target, field set, revision, request or transaction.

Keep subject activity, tenant membership and existing kind-specific ACL/native ceilings current. Assignment and owner-candidate adapters require an active referenced owner; historical reference disclosure must not accidentally inherit a new universal active-owner rule when the existing reader exposes inactive-owner IDs/labels. Similarly retired domains and tombstoned relations retain historical identity and applicable denies. The design preserves this existing kind-specific target ceiling and historical-owner compatibility rule. The field loader records the actual current activity facts and the adapter-specific use instead of guessing from a missing label. No unrestricted side-loader may use the parent's success as general read access.

## 3. Proposed finite static FieldId catalog and alias bindings

## 4. Trusted dynamic attribute and source-observation registration

### Authored attributes

A raw dotted key is not a field selector: attribute keys themselves may contain dots (`model.ts:73`), object/list structure is explicit, and JSON Pointer escaping is a diagnostic encoding rather than authority. Store a protected registry entry with canonical owner kind/UUID, stable logical field UUID, parent field UUID, typed segment (`property` with exact key or `list-element`), exact definition-version coverage, origin/dependency links and schema digest. The proposed dynamic FieldId encoding is `attribute:<registrationUUID>:schema` or `attribute:<registrationUUID>:value`, accepted only after a protected lookup for the exact owner/pin/origin and role. Its UUID is assigned by the trusted publisher; the grammar alone never registers a field. No user chooses a registration UUID in a definition/value API body. A list position is not a new field identity and cannot be used to grant only whatever item happens to occupy index3.

Registration occurs only while publishing a fully validated canonical definition under its real publication action and authority lock. It enumerates the bounded declared schema tree, including containers, nested properties, list-element schemas, labels, requiredness, constraints and enum literals. Runtime input parsing and source scans cannot register policy fields. Preserve a field identity across later versions of the same logical property; changing constraints/type does not reset a deny. Removing then reintroducing the same key must not accidentally reset sensitivity. A true semantic replacement, rename, or explicit alias needs reviewed registration provenance; default rename creates a new entry with no automatically inherited positive field grant, while old historical entries remain.

For inheritance, every resolved property stores the exact origin property registrations from the pinned parent closure. The flattened model alias, authored local definition and resolved inherited view share those entries. Multiple inheritance/explicit override must not erase a parent's deny or sensitivity: require the inherited-origin entries plus the child's effective entry where it differs. The design must specify whether an approved override can replace an origin classification; until then, use the conservative union. Definition schema fields and instance values are separate field roles under the same logical registration; denying value access never implies that an allowed schema label can reveal the actual value.

The actual attribute grammar is closed at `model.ts:28–46`: text/richText, number(integer/min/max), decimal(precision/scale/string min/max), boolean/date/timestamp/duration, enum values, list(items/min/max), URI(schemes/maxLength), and object(properties); definitions optionally label/require a field. Unknown schema nodes, bad pins or missing history-to-registration companions yield indeterminate/whole-object denial. Do not reparse an immutable value using only today's head definition. Registration must refer to the exact schema version used by the value/revision and current sensitivity state of its stable field identity.

### Source metadata, including existing arbitrary keys

`ScanRecord.metadata` currently accepts arbitrary JSON values (`packages/contracts/src/index.ts:6`), and legacy asset metadata has no authored model grammar. **Do not force these opaque values through authored-attribute validation, mutate them, or infer approval/classification facts from them.** The selected baseline for this candidate is an atomic registered `asset.metadata` container plus reviewed connector leaf registrations. The container and applicable registered leaves are checked together. An unknown key is covered by the opaque container obligation and is never silently discarded or promoted to a new trusted field.

For the current pinned PostgreSQL producer, propose the following literal leaf IDs: `asset.observation.{oid,relationKind,schema,table,dataType,nullable,ordinalPosition,primaryKey,sourceDescription,sourceDescriptionTruncated,provenance,sourceVersion,scanId,aliases}`. Actual producer locations: `python/governance_workers/postgresql.py:58–75`; API completion adds/overwrites sourceVersion/scanId/provenance/aliases at `index.ts:110`. Schema records emit oid/provenance; relation records emit oid/relationKind/schema/table/sourceDescription/sourceDescriptionTruncated/provenance; column records emit dataType/nullable/ordinalPosition/primaryKey/sourceDescription/sourceDescriptionTruncated/provenance. SourceVersion is server-version text, not a canonical source row version.

These leaf selectors are registered by the trusted connector adapter version and exact emitted variant. Their presence is not proof that an arbitrary old asset's same-named key has that provenance. Keep protected provenance/source/job/version bindings for new observations; historical values require an explicit reviewed legacy attribution rule or the atomic opaque metadata policy. Additional connectors need their own exact field catalog and review; arbitrary client/connector key paths are never active policy IDs.

Duplicate semantic disclosures require dependencies: the current relation metadata `table` is emitted from the same `relname` as asset.name and therefore also requires that asset.name field; `scanId` references the actual scan job; `aliases` contain earlier qualified names and require current permission for the qualified-name semantic field. Qualified names can include database/schema/parent names; producer-origin dependencies must be recorded rather than guessed by splitting user-controlled strings. Do not claim arbitrary opaque text has been semantically classified. A new sensitivity activation needs an impact rule for unknown/legacy payloads and repeated literals; the safe default for indeterminate required dependencies is whole-object denial. Root must freeze this historical attribution rule before activation.

## 8. Freeze and coverage gates; unresolved details

Before implementation, root should freeze a machine-readable registry containing each expanded AdapterId, literal action/resource applicability, projection schema digest, leaf/container bindings, dynamic origin registry, reference-disclosure rule, trusted purpose/environment provenance, cardinality/budget accounting, error mapping and replay requirement. The following checks are required and have **not run** for scoped authority:

1. AST/static route-and-service inventory matches all registered current routes/command branches; all response fields/union arms have bindings; no permissive generic serializer, callback, additionalProperties or unbound nested receipt path remains. Ordinary DTOs without schemas gain exact schemas preserving existing bytes.
2. Exhaustive ten-string subset parity uses a separate legacy predicate oracle, including operation-response fields without SR/MR, embedded attributes with CR, selector differences and empty/inactive memberships. New sensitivity and deliberate deny activation is separately impact-reviewed.
3. Alias regressions deny the same field through current/embedded/history/audit/receipt/search paths, including joined owner/source/type labels, actual source-observation duplicates, model/type alias identity, dynamic nested lists/properties and immutable old versions after rename/migration.
4. Real SQL/API tests prove no early materialization/count/sort/page/facet exposure, original-scope replay after moves, a denied required mutation result leaves zero canonical/journal/success effects, and an allowed optional omission uses only the declared optional shape. Hash-bearing documents are never silently rewritten.
5. Worker tests cover initiating human and service revocation at dispatch/claim/complete/fail/terminal replay, security generation/fences, source native privilege ceilings, paused index projection, complete reconciliation and absence of source metadata/secrets in Temporal history.

Concrete open items preventing a false catalog-complete claim:

- Concrete SQL/service realization of the root-selected narrow-reference tuple and protected resource-wide intent marker, including the adopted existing kind-specific activity and historical-owner compatibility rule; no new reference actions are added.
- Generate and review the literal machine registry from the exact migration/context/preview/preparation and journal variants in sections9–10; prove every leaf/container and union arm is bound. Their enumeration is source inspection, not an executed schema-coverage proof.
- Dynamic inherited/overridden field origin identity, rename/reintroduction behavior and old historical companions; new source-observation provenance versus opaque legacy metadata must have an explicit migration rule.
- Administration/bootstrap DTOs are being designed separately and are not existing ingress. Their exact adapters must join the same registry before activation. No registry string grants administration by itself.
- Shared aggregate field/scope limits and SQL/TypeScript equivalence must be frozen with the storage protocol. Existing per-engine physical limits and original deadlines remain ceilings and cannot be enlarged or reset by this catalog.

This is a source-backed candidate for a shared contract, not a claim that the proposed scoped field engine, registrations, leases, new DTOs or cutover gates exist.
