## 3. Cookies, attempts and replay

All cookies are host-only, SameSite=Lax and HttpOnly. Production names are `__Host-gc_authn_session`, `__Host-gc_authn_csrf`, `__Host-gc_authn_attempt`, Secure=true, Path=/; explicit local HTTP names are `gc_authn_session`, `gc_authn_csrf`, `gc_authn_attempt` with Secure=false, Path=/authn. The environment selects exactly one family; do not accept both. No Domain, browser storage, bearer token, raw ID token or refresh token. Clearing uses the identical names/path/security attributes. Local paths prevent new cookies being sent to Keycloak /realms: different localhost ports alone do not isolate cookies. Isolated browser qualification uses a fresh browser context, never existing user tabs or cookies. Production requires a distinct IdP hostname, or a separately qualified edge that strips app cookies before every IdP upstream; no __Host cookie may use a non-root path.

1. Login generates independent32-byte cryptographic state/nonce/session/CSRF values as appropriate; verifier is an independent43–128-character compliant random value. `attemptBegin({stateHash:SHA256(rawState),verifier,nonceHash:SHA256(rawNonce)})` commits. Set attempt cookie as strict `attemptUUID.rawState` (canonical UUID and43-character base64url state), expiry no later than DB attempt expiry. Send raw state/nonce and S256 challenge to the exact authorization endpoint. No trusted identity/tenant input exists.
2. Callback requires exactly one bounded attempt cookie and constant-time equality of returned raw state. Derive ID/hash from that cookie and call `attemptConsume`. Clear the attempt cookie. Only after its successful COMMIT may the broker contact token endpoint. Consumed issuer/client/callback must exactly equal broker's pinned configuration; mismatch fails with no token exchange/issuance. Authenticated IdP error responses also consume the matched attempt and produce a fixed safe failure; malformed/mismatched state cannot consume someone else's attempt.
3. Callback validates the actual token and calls `sessionIssue` once. Set new random session/CSRF cookies only after confirmed commit, with remaining Max-Age bounded by returned DB expiry (never fixed renewal). Uncertain consume/issue response is a failed attempt requiring a new sign-in, not replay issuance. Private orphan sessions expire naturally; no invented successful logout/compensation is reported. Existing protected sessions are not silently asserted revoked when a fresh login replaces browser cookies; explicit logout owns revocation.
4. Attempt300s, issue within60s after committed consume and before original expiry, session≤1800s clamped by registration/binding expiry: SQL remains authoritative. No sliding renewal, refresh-token flow or silent legacy session migration. Multiple login tabs use latest attempt cookie; superseded attempts fail and expire rather than sharing a global single-use map.

All authn responses use Cache-Control:no-store, Referrer-Policy:no-referrer, restrictive CSP/self-hosted JS, frame-ancestors:none, nosniff, and no third-party assets. Never log URL/query/body/cookies/CSRF headers/token responses/claims/session hashes or SQL arguments. Log fixed error code+request correlation only. Disable token/code-bearing traces and test artifacts; browser video/trace must be disabled or scrubbed before publication.

## 4. Bounded OIDC/JWKS transport and Keycloak configuration

Use pinned jose6.2.17 from current lock; actual installed remote JWKS API supports `customFetch`, `timeoutDuration`, `cooldownDuration`, `cacheMaxAge`. Wrap fetch with exact-URL allowlist, redirect:error/manual with all3xx refused, total timeout5s for metadata/JWKS and10s token, streamed byte accounting including absent/false Content-Length and decompressed bytes. Abort/cancel on overflow; do not call unbounded response.json(). Caps: metadata32KiB, JWKS128KiB, token response64KiB, compact ID token16KiB, decoded header2KiB/payload8KiB, JSON depth8/nodes2048. Strict UTF-8/duplicate-key parsing before signature verification is syntax admission only. No externally persisted JWKS cache.

Metadata is startup-fetched from only the configured issuer alias, exact issuer checked, and discovered endpoints must match explicit configured endpoints; it cannot expand the network allowlist. Missing/unavailable/oversized metadata makes readiness unavailable. OIDC configuration is server-owned, never selected by a callback/header. In-memory JWKS cache max5min, missing-key fetch cooldown30s, one coalesced fetch per issuer; fail closed on unavailable/expired cache. At most32 total keys, unique bounded kid, applicable RSA signing keys2048–4096bits, no private key members, fixedRS256; reject malformed/ambiguous signature candidates. Non-applicable public encryption/other-algorithm keys remain counted and structurally bounded, but never selected as a signing candidate; do not reject a valid Keycloak set merely for containing an unrelated encryption key. Ignore token-supplied remote key locations: reject jku/jwk/x5u/critical extensions in this profile. No algorithm fallback.

Require signed claims iss/sub/aud/exp/iat/nonce/auth_time; check exact issuer; audience string exact clientId or unique bounded array≤8 containing it, with azp required for multiple audiences and equal clientId whenever present. Validate nonce by SHA256 against consumed nonceHash. Numeric dates must be finite nonnegative integer seconds safely convertible to exact canonical UTC milliseconds; no rounding/fallback. Verify auth_time≤iat≤now, exp>now and exp>iat; SQL repeats authoritative clock/attempt/binding checks. Broker attests audience=registered clientId only after these checks. Hash the exact original compact token. Discard all tokens after issuance; access/refresh token fields may be returned by Keycloak but are never persisted, sent to browser or used to extend session.

Add a distinct public Keycloak client `governance-protected-web`, leaving `governance-web` untouched: standardFlowEnabled=true; implicitFlowEnabled=false; directAccessGrantsEnabled=false; serviceAccountsEnabled=false; exact redirect `http://localhost:4310/authn/callback` (4314 in isolated profile); exact web origin; attributes `pkce.code.challenge.method=S256`, `id.token.signed.response.alg=RS256`; defaultClientScopes includes built-in `basic`. Request `scope=openid`, `response_type=code`, `response_mode=query`, `max_age=0` and essential auth_time claim. Read back that the built-in basic scope's auth_time mapper is present and contributes to ID tokens; do not substitute a static/user-editable claim mapper. New client configuration must be applied/read back explicitly for an existing realm: startup import alone is not an update guarantee. Keep full fixed KC_HOSTNAME and fail on disagreement, never hostname-strict=false as a workaround.

OIDC Core requires auth_time when max_age is requested, and max_age=0 requests fresh authentication. The broker verifies actual presence and ordering; additionally propose `auth_time >= consumedAttempt.expiresAt - 300seconds - 30seconds`. Current SQL012 attempt_begin stores and returns exactly created_at+300seconds (lines650–652), and consume returns that same immutable expiry; this bound therefore uses protected DB time, not a caller cookie timestamp. Root adoption is required for this additional transport freshness rule. SQL retains its unchanged ordering/window checks. Mandatory auth_time itself is not optional. [OIDC Core §§2,3.1.2.1,3.1.3.7](https://openid.net/specs/openid-connect-core-1_0.html).

Keycloak's basic client scope supplies the auth_time mapper; this is documented separately from runtime qualification. [Keycloak25 upgrade notes](https://github.com/keycloak/keycloak/blob/main/docs/documentation/upgrading/topics/changes/changes-25_0_0.adoc#new-default-client-scope-basic). Fixed hostname and correctly overwritten proxy headers are required when proxying IdP endpoints; this proposal does not trust browser-provided forwarding headers. [Keycloak hostname](https://www.keycloak.org/server/hostname), [reverse-proxy configuration](https://www.keycloak.org/server/reverseproxy). ## 5. Protected lifecycle semantics and small real page

GET `/authn/session` accepts only protected session/CSRF cookies; hashes session and returns actual `AuthenticatedSession` plus raw CSRF from its transport cookie. The raw value is not returned by SQL. A modified CSRF cookie cannot authorize a mutation because select/revoke verify its hash against private storage. No names, tenant inventory, permissions, Principal or content links are fabricated. Missing/invalid session returns401. The page presents signed-in/inactive-content state, current tenant UUID, exact session version/expiry, a UUID tenant-selection input and logout; keyboard/EN+AR/RTL/mobile support applies. It is a real qualification surface, not a replacement product shell or capability-completion claim.

POST routes require exact Origin==publicOrigin (missing/null rejected), JSON content type, no query parameters, header rawCSRF constant-time equal cookie value, and SQL CSRF hash/version validation. Select body is exact above; `replacementCsrfHash` comes only from a newly generated server value. Set replacement cookie only after commit; stale-version409 does not rotate cookies or retry a mutation. UI reloads current descriptor before new consent. A lost response after committed rotation leaves old CSRF unusable: reauthentication is the safe recovery, never rollback/overwrite private session state. Logout uses supplied last-known version directly; do not pre-require membership-active inspection, which would prevent the supported SQL logout-after-membership-revocation case. An admitted logout (exact Origin, valid cookie/header CSRF and valid closed body) clears protected cookies even when revoke fails or its commit is uncertain. Invalid Origin/CSRF/body must not clear cookies. Only confirmed revoke reports loggedOut:true; an uncertain failure explicitly means browser credentials were cleared without a confirmed server revocation. Logout is local protected-session revocation, not an unimplemented IdP-wide logout claim.

Closed safe HTTP errors:400 AUTHN_REQUEST_INVALID;401 AUTHN_LOGIN_INVALID or AUTHN_SESSION_REJECTED;403 AUTHN_CSRF_REJECTED or AUTHN_SELECTION_REJECTED;409 AUTHN_VERSION_CONFLICT;429 AUTHN_RATE_LIMITED;503 AUTHN_UNAVAILABLE. Callback provider/token/binding failures share generic401, not identity/member enumeration. Invalid executor/DB transport is503 and operator diagnostic only. Every error has correlation ID, no raw cause/details. Application/logout errors distinguish a confirmed private revoke from cookie-only clearing. Add bounded30/minute login+callback rate limit per admitted edge address and16 process in-flight cap; forged forwarding headers cannot choose rate-limit identity. Global admission is still enforced when proxied addresses collapse.
