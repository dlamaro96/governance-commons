## 2. Aggregate implications

1. **Logical scope, retained representation and decision work are separate dimensions.** Existing code has no universal maximum resource count, field count or authorization-decision count. A cap derived from one operation's largest constant is not a compatibility proof.
2. **Optional fields create a multiplication risk.** A 1,000-asset model cohort sharing 128 optional top-level fields with sparse/empty values has up to 128,000 resource/declared-field combinations per phase without needing 128,000 stored value nodes. Before/after or source/target checks multiply work again; nested field inventories can exceed 128. This is source-derived combinatorics, not an executed maximum-size fixture or a claim that all profile maxima coexist.
3. **Repeated projections are not distinct canonical resources.** A semantic field can recur in a definition, current/proposed tuple, history, receipt and digest dependency. Every occurrence keeps its security obligation, but materializing every occurrence into authority JSON can exceed a new 512-KiB envelope even when differently charged existing representations fit.
4. **Do not sum independent ceilings into a supported total.** Graph counters suggest 2,000 + 1,000 + 4,000 active members before type pins; SQL010's physical budget prevents some such combinations. Conversely, this baseline does not prove that a new 1,000- or 2,000-member total cap preserves every accepted scope. A smaller scalar cap needs an explicit scope contract and compatibility evidence.
5. **2,001 principal locks do not cap authorization populations.** They serialize an operation's referenced principals. Future groups, grants, role evidence and applicable policy sets need separate admission contracts; existing tenant membership storage has no such population cap.
6. **Visibility ordering is semantic.** Complete-scope authorization precedes exposed counts/size failures. Exhaustion cannot return a partial preview, authorize a page of a compound mutation, drop preserved participants, weaken a deny, or emit totals from an incompletely authorized set.

## 3. DRAFT scope-preserving evaluation proposal

This section is for root review. It is not an implemented evaluator, adopted numeric budget, or permission to alter applied migrations.

- Preserve each operation's existing scope discovery, count, physical-byte, node, version, deadline and error semantics as independent guards. Authority-only metadata must not consume a legacy business-payload budget unless a separately adopted contract changes that accounting. Both layers must pass; neither enlarges the other.
- Give authority distinct named budgets for policy admission, canonical facts/role evidence, compiled descriptors, temporary memory, memo entries, explanation output and execution time. Specify units, distinct/repeated accounting, phase/lifetime, overflow behavior and SQL/TypeScript equivalence. An arbitrary total resource or field-pair ceiling does not supply this contract.
- Use a protected canonical descriptor covering authenticated subject/tenant; exact action; canonical resource identity/kind/revision and old/proposed role; registered semantic field/schema pin; registry version; current authority generation/fence; exact subject/group/role evidence and relevant approved facts. Callers cannot choose cheaper descriptors or omit influencing dependencies.
- Memoize only identical complete descriptors within the same authorized evaluation window. Parse/compile policies once at exact immutable policy/registry pins. Keys include every decision input and consistency/time dependency. Proposed/historical values cannot reuse current-value decisions just because UUIDs match. Generation changes, revocation, changed facts/evidence and expiry boundaries invalidate affected reuse. No cross-request/transaction authorization cache is adopted here.
- Stream bounded canonical batches over the complete scope instead of materializing a resource × field × policy Cartesian product. Memory/memo limits may evict and recompute, never drop remaining decisions. Preserve the stable snapshot/fence and complete deny checks. Early termination is safe only once the whole operation is denied and its response is non-disclosing; an early allow cannot skip possible denies.
- Bound parallel work and preserve the original deadline. Authorization still precedes counts/facets/ranking and protected payload loading. Streaming cannot deliver partial externally visible results for indivisible previews, receipts or mutations. Commit still requires every obligation; internal batch completion is not a capability.
- Bound explanations separately from decisions. Any abbreviated diagnostic output needs the adopted DTO's explicit completeness behavior; it cannot truncate evaluation or change immutable receipt formats. New DTOs require their own reviewed contracts.
- Before activation, prove compatibility under admitted authority state: equivalent legacy predicates preserve complete allowed/denied scopes and fail-closed behavior under unchanged business profiles. If finite authority admission/execution limits cannot preserve that contract, expose the exact proposed scope/profile change for product review rather than concealing it in an implementation constant.

The authority candidate already specifies a **per-definition** AST proposal of 128 expression nodes, depth 8 with root depth 1, 64 KiB UTF-8 definition size, at most 128 rules, finite sets at most 256 entries and 32 canonical domain ancestors (`SCOPED_AUTHORITY_CONTRACT_CANDIDATE.md:206`). It leaves aggregate policy/grant/principal budgets to freeze (`:365`). Per-definition bounds do not bound the number of applicable definitions or the subject evidence closure.

## 4. Admission contracts required before activation

No numeric value below is adopted here. Product/storage contracts must decide these finite dimensions and enforce them at mutation/import/provisioning boundaries. Existing or over-limit data requires an explicit migration/disposition; evaluation must never silently ignore it.

| Admission dimension | Required contract |
|---|---|
| Applicable policies | Maximum active applicable definitions/rules and cumulative compiled bytes/nodes for a subject/action/resource scope, including inherited denies; applicability indexing, historical pins and time windows. Per-definition AST limits are insufficient. |
| Grants/bindings | Maximum active direct/group role assignments, responsibilities, relation grants, denies and field assignments contributing to a decision or subject scope; cumulative payload bytes, deduplication identity, expiry/revoke treatment and publication impact. No first-N/rule-order truncation. |
| Group membership | Maximum direct memberships per subject, group size where relevant to evaluation/administration, cumulative membership evidence bytes, atomic import/provisioning behavior and existing-data disposition. Nested groups remain unsupported by the candidate. The 2,001 operation lock bound is not a tenant user/group cap. |
| Role evidence | Maximum request-scoped assignment records, role pins and aggregate policy descriptors after current scope/field checks. Roles in unrelated domains do not confer authority here; caller claims cannot replace canonical evidence. |
| Delegation/elevation | Maximum chain depth, active ancestors/fan-out/evidence, expiry and delegated field/action scope; issuance/revocation/dependent-use semantics. Bounds cannot bypass current ancestor revalidation. |
| Registered fields/approved facts | Maximum field/schema registration descriptors, applicable sensitivity/classification/tag facts and retained bytes for an admitted decision. Accommodate existing nested grammar and old/proposed pins; 128 per-object properties is not the complete field count. |
| Service authority | Exact A1/service scope, concurrent claims, lease lifetime, renewal/reallocation and failure-recovery limits with source/site/issuer provenance and original deadline preservation. Human membership/ownership does not supply service authority. |
| Operational resources | Bounded memory, concurrency, queries/dependency retrieval and elapsed time per adapter/profile; safe errors and whole-operation failure. Include the cost of recomputation after memo eviction and demonstrate compatibility with the original window. |

Before freezing numbers, review sparse/dense schemas, existing maximum cohorts, mixed/historical pins, domain ancestor unions, preserved/released graph participation, many matching denies, broad group memberships, grant churn and repeated before/after/history/receipt projections. Subsequent unit/equivalence, real PostgreSQL runtime-role, revocation/concurrency and relevant HTTP/browser gates must bind exact source and workload. None ran for this document.
