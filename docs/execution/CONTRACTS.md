## M2 attribute-model increment (2026-11-15)

Published definitions use ModelDefinition from packages/domain/src/model.ts, with safe logical text id (not asset UUID or source asset.type), formatVersion1, positive version and typed attributes. governance_models stores the tenant-scoped current head; governance_model_versions is immutable. Assets pin model_id/model_version and separately store governed attributes. Source scans preserve these values. No automatic reinterpretation or migration occurs on new model publication.

Permissions: models:read for schema reads; models:write plus catalog:read for preview/publication; catalog:read/write plus models:read for asset assignment. Service rechecks active memberships. No hidden asset names, IDs, counts or values appear in model previews. A cohort containing inaccessible bindings fails with generic MODEL_SCOPE_UNAVAILABLE. Preview enumerates canonical data server-side, bounded to1,000 assets and512KiB attribute JSON; incomplete scope never yields a safe publication claim. Model publication/assignment serialize through a common tenant model lock; previewDigest binds exact head, proposal and current asset versions/values. Immutable asset revisions, audit and outbox commit with each mutation.

GET /api/v1/models?limit=&cursor=&q= -> {items:[{id,currentVersion,createdAt,createdBy}],nextCursor:null|string}. Default50/max100 rows per page, stable ascending logical ID keyset, literal case-insensitive ID substring search (max64 characters). Opaque HMAC-SHA256 cursors bind tenant, actor, literal search, page size and fixed id:asc sorting. Signature and canonical encoding are checked before payload use; every page reauthorizes and queries forced-RLS canonical rows. Signing is domain-separated from other cursor purposes using the configured SESSION_KEY; absent/short keys fail closed. Rotating that key invalidates existing cursors; restart from page one. Cursors are selectors, not authorization grants. The wire format is internal and must not be constructed by clients. Pages are live reads rather than an inventory snapshot. UI uses20-row pages with explicit search and previous/next controls. GET /models/:id and /models/:id/versions/:version -> {model:{id,version,currentVersion,definition,definitionHash,createdAt,createdBy}}. POST /models/validate {text} retains raw imported JSON for duplicate-key detection -> {definition}; invalid models return problem+json with issues:[{code,path,message}]. POST /models {definition}, Idempotency-Key ->201 {model}.

POST /models/:id/previews {definition}, If-Match currentVersion -> {preview:{modelId,currentVersion,proposedVersion,coverage:'complete-tenant-model-bindings',assetCount,changes,assets:[{assetId,currentIssues,proposedIssues}],affectedAssetIds,compatibleWithProvidedAssets,requiresExplicitMigration,pinsPreserved:true,previewDigest}}. POST /models/:id/versions {definition,previewDigest}, If-Match + Idempotency-Key ->201 {model}; destructive/incompatible proposals require the separate explicit migration path below. Stale preview digests or heads conflict; publish rechecks under lock.

GET /assets/:id/attributes -> {assetId,assetVersion,modelId:null|string,modelVersion:null|number,attributes,definition:null|ModelDefinition}. PUT same path {modelId,modelVersion,attributes}, If-Match assetVersion + Idempotency-Key -> updated attributes response and ETag. Cached mutation responses still require current canonical asset visibility. Definition versions and asset edit versions are distinct. Decimal values stay strings; rich text is safe source text. No executable expressions.

This increment remains partial MOD: inheritance, relation constraints/validity, layouts, completeness, bulk/workflow/MCP ingress and typed search/sort/export across all assets remain required next work. Model file export is a round-trip of the immutable definition, not a claim of full portable catalogue export.

## Explicit bounded model migrations (2026-11-15)

SQL004 is already applied and immutable. SQL005 adds receipt integrity without rewriting existing migrations. Browser and storage qualification are pending until recorded in their separate evidence files.

The shared MigrationPlan is declarative data: formatVersion1, modelId, targetVersion, sorted unique sourceVersions matching actual asset pins, exact acknowledgedChanges for destructive schema changes, and up to64 ordered operations. Operations are rename, remove, set (ifMissing/replace), enumMap (explicit unmapped policy), and conversion (safeIntegerToDecimal, decimalToText, textToDecimal). Missing-path handling is explicit. No executable expressions, implicit parent creation, list-index mutation, trimming, rounding or precision-losing coercion. Raw JSON import rejects duplicate keys including escaped equivalents. Model and migration files have distinct parser budgets; migration acknowledgements support the full2048 schema-node bound.

- POST /api/v1/models/migration-plans/validate {text} -> {plan}.
- GET /api/v1/models/:id/migration-context -> {modelId,currentVersion,sourceVersions,assetCount}. Requires current model/catalog read and write permission and complete cohort visibility.
- POST /api/v1/models/:id/migration-previews {definition,plan}, If-Match currentVersion -> {preview}. Preview includes modelId,currentVersion,proposedVersion,coverage:'complete-tenant-model-bindings',assetCount,changes,planHash,previewDigest,ready:true and assets with assetId,from/toAssetVersion,from/toModelVersion,before/afterHash,before/afterAttributes.
- POST /api/v1/models/:id/migrations {definition,plan,previewDigest}, If-Match + Idempotency-Key ->201 {model,receipt}. Requires current models:read/write and catalog:read/write. Every response, including idempotent replay, reauthorizes the originally recorded assets and current write permissions.
- GET /api/v1/models/:id/migrations/:migrationId -> {receipt}. Requires current model/catalog read permission and visibility of every original receipt asset, even if an asset has since changed model.

Receipt fields: id,modelId,fromVersion,toVersion,plan,planHash,previewDigest,assetCount,assets,executedBy,executedAt. Asset entries contain versions and hashes, not attribute values. The plan may contain literal values, so the complete receipt remains cohort-authorized. Model-level audit summaries omit asset identifiers, counts and plan literals; asset events follow asset visibility.

All mutations run in one PostgreSQL transaction using ledger → model → head → ordered asset locks. Validation and fresh digest comparison precede writes. The transaction includes the new immutable definition, head, all bound pins and values, immutable revisions, receipt, production audit and outbox. A failure aborts the entire mutation. A separate sanitized model.migration_attempt_failed event records request/attempt failure; it never claims that a previously committed migration was rolled back when a replay is denied.

The synchronous development profile bounds complete cohorts to1000 assets, each aggregate before/after attribute set to512KiB and100,000 nodes, distinct historical definitions to512KiB/100,000 nodes, and issues to1000. Overflow fails the whole operation. Bulk/resumable Temporal migrations remain required future work. See ADR0004 and the model-migration recovery runbook; no post-commit downgrade or restore qualification is implied.
