3. Add only the owner-only `gc_authn.foundation_session_v1(text)` bridge and its private type. Preserve SQL012 executor safety and its exact three API capabilities. Original native session_user/database and real protected session provenance are required; no API role impersonation, legacy session fallback or caller-authored principal is accepted.
4. Implement complete conservative candidate selection for the exact root requests and recursively required human issuer requests. Retain full policy pins, future memberships, resource-wide intents and exact revoked/expired via-membership history. The entire PrincipalGroups ref union pays its existing1024 proof bound. Refuse over-limit closures without truncation; production scope/profile preservation remains unqualified until the later canonical scope-aware adapter.
5. Elevation projection selection is deterministic: current exact-session use, otherwise earliest future use. Preserve the full needed inventory. Persist separately keyed grant-base, use DTO and embedded-use measures; charge every serialized occurrence and validate materialized counts/hashes.
6. Follow tenant ledger/fence, required SQL012 configuration/fence, sorted principals and exact session/use lock phases. Discover the required configuration lock set before principal locking; refuse late discovery. Read loaders use fresh read-only repeatable-read transactions, original deadlines, scalar preflight and no read-time writes.
7. The owner is the deployment trust root. Synthetic fixture writes test integrity and are never represented as authorized administration, installation consent, production facts or an audit approval. Loader output remains private inactive candidate evidence with `contentAuthority:false`.

## Integration refinements adopted before implementation

The closure DTO intentionally contains an exact registry pin rather than its complete field catalog. Full TypeScript consistency parsing therefore takes the separately validated registry: `parseAuthorityHumanClosure(value, registry)`. The repository reads that exact registry triple from private storage in the same fresh read-only repeatable-read transaction after its single loader call. Fixed parameterized SQL performs scalar byte/node preflight before retaining the registry text. Independently validate the closed registry, frozen action catalog and canonical digest against the closure pin. The retained registry plus closure share the existing8MiB/262144node/depth32 physical bounds in the wrapper; neither a second query nor parser resets a budget. The closure's own metrics still describe its exact serialized closure. All queries, validation and commit remain inside the original30second wall deadline with one outstanding query. A standalone syntax parser without an exact registry cannot claim registered-field consistency or provenance.

SQL013 reuses the existing exact SET-only transfer membership staged by `authentication_roles.prepare_sql`. As owner of the existing gc_authn schema, its migration transaction temporarily grants CREATE there to gc_authn_definer solely for new bridge/type ownership transfer, then revokes it in the same transaction. Existing `finish_sql` remains mandatory on success/failure and removes only its associated temporary privileges. Do not widen ordinary startup preparation, runtime API allowances or old migration bytes. Native gates must verify final ownership, all ACLs and failure cleanup independently.

Human loader selectors reject SERVICE actions with SQLSTATE22023; all valid human and FIELD selectors retain the exact existing field grammar. `policyBytes` sums canonical parsed PolicyDefinition bytes, matching the pure engine; raw retained policy text is charged separately by physical preflight, not double-counted against the semantic2MiB policy limit. `proofBytes` sums canonical lengths of complete arrays principals/groups/memberships/principalGroups/definitions/partitions/grants/elevationUses/parents/dependencies/lifecycleHeads, each array framing included, plus the canonical session object. This conservative foundation measure does not replace later full-engine proof accounting. Full closure canonicalBytes includes metrics and is derived by a decimal fixed point initialized at0, with at most4 rounds and explicit refusal if not stable. Nodes/depth describe the full result. closureDigest excludes metrics and snapshot.closureDigest only.

The finite write-begin signature cannot know later principal/session references. Add private normalized `write_lock_claims(transaction_id xid8, tenant_id uuid, phase, kind, object_id uuid)`, with primary key(transaction_id,phase,kind,object_id), write_bindings/tenant integrity and forced RLS. Owner-only `foundation_write_locks_v1(principal_ids uuid[],session_ids uuid[])` runs exactly once after begin and before canonical child DML. Inputs are canonical distinct bounded sets, at most2048 principals/1024 sessions. It derives configuration references from actual sessions, locks configuration then sorted principals then exact sessions, and seals only after a fresh session read matches the discovered tuple. Changed references refuse without acquiring configuration late. Closed phase/kind pairs are configuration(login-generation,executor,issuer,binding,authn-tenant), principal(identity,member), session(session), sealed(tenant). login-generation object_id is the login channel UUID; the sealed object is the bound tenant. Exact result is `{formatVersion:1,tenantId,principalCount,sessionCount}`. Immutable claims bind the original transaction, backend, owner and tenant. Every child/lifecycle write requires the seal and its exact relevant principal/session claims; late expansion, reused context, empty begin or claim-only commit refuses. No caller configuration ID or GUC supplies proof. This is a finite private fixture/internal locking protocol, not authorized administration.

PostgreSQL per-schema default privileges are additive. SQL013 revokes the global implicit PUBLIC EXECUTE/USAGE defaults for future functions/types created by the native migration owner and gc_authn_definer in this database. Existing SQL001–012 object ACLs are unchanged. Future trusted migrations must explicitly grant each intended capability. Native rollback probes must create actual future objects and verify denial, both creator default entries and all preexisting function ACLs. This creator-wide scope is required to prevent a future private overload from inheriting PUBLIC access.
