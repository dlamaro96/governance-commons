# Real API qualification

Run `./dev up --profile core`, `./dev seed --dataset harbor-demo`, then `./dev test --suite security`. Use the pinned Node toolchain documented in the root README. The security command runs the actual API/PostgreSQL integration files, serially, against the current Compose services. A successful test does not qualify every security requirement or an external connector.

The runner checks the executed test bytes before and after execution. It retains bounded private TAP and an invocation summary under ignored `.local/evidence/api-runs/`. The latest `.local/evidence/api-summary.json` is invalidated at the start of each invocation. Public evidence contains only declared test coordinates, counts, fixed diagnostic flags and hashes. Preserve a failed invocation before retrying; never publish raw TAP or substitute an earlier successful summary.

HTTP tests explicitly import `tests/fixtures/http-budget.ts`. Admission is paced at 500 ms while concurrent in-flight requests remain concurrent. There are no automatic request retries, and the production 300/minute rate limit stays unchanged. New HTTP integration files must use the same fixture and keep single-worker execution.

Direct completion-handler cases supply controlled synthetic worker observations to real handlers. `tests/fixtures/manual-scan.ts` reserves each exact Temporal workflow ID on a unique unconsumed queue **before** inserting its running job. It verifies that no workflow task ran. Cleanup confirms that the actual job is terminal before terminating the exact owned workflow run; uncertain cleanup fails the test and retains the reservation. These cases do not establish connector execution. The source/browser journeys separately use the ordinary dispatcher, site runner and real PostgreSQL source.

An interrupted process can bypass cleanup. Private errors include the owned synthetic job, workflow, run and queue identifiers. Before terminating such a reservation, inspect that exact job and its source/actor, invoke the authenticated internal failure handler if it is still runnable, and read back its terminal database state. Verify the exact workflow run and fixture ownership marker before termination. Never terminate by a broad workflow prefix or release a reservation while its job may still run. Reservations expire after 30 minutes; recovery must precede expiry. A hard-kill recovery drill is not yet qualified.

The audit regression creates more than 10,000 hash-valid synthetic events inside a real rollback-only transaction and verifies that hidden history is denied before the development size limit. It confirms that no fixture audit, asset, revision, outbox or session rows persist. PostgreSQL sequence allocation advances even on rollback; this is not a byte-identical sequence-state recovery test. The public integrity reader uses one read-only repeatable-read snapshot for current session, membership, visibility and bounded chain materialization.
